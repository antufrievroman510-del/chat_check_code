# 📡 2PC РЕЖИМ ЧЕРЕЗ UDP - ПОЛНАЯ ИНСТРУКЦИЯ

## 🔍 ПРОБЛЕМА
Ранее использовалось подключение через COM-порт Makcu, но нажатия кнопок мыши с ПК №1 не передавались на ПК №2.
Причина: прошивка Makcu не отправляла события нажатий через UART/COM порт.

## ✅ РЕШЕНИЕ
Используем UDP для передачи нажатий кнопок между двумя компьютерами:
- **ПК №1**: Запускает программу `MakcuUdpSender.exe` - перехватывает нажатия мыши и отправляет по сети
- **ПК №2**: Чит PWNZ AI слушает UDP порт и получает нажатия

---

## 📋 ШАГ 1: НАСТРОЙКА СЕТИ

### Узнайте IP адрес ПК №2 (где запущен чит)
На ПК №2 откройте командную строку и выполните:
```cmd
ipconfig
```
Найдите IPv4 адрес вашей сетевой карты (например, `192.168.1.100`)

### Проверьте связь между ПК
На ПК №1 выполните:
```cmd
ping 192.168.1.100
```
Должны идти ответы. Если нет - проверьте настройки сети и брандмауэр.

---

## 📋 ШАГ 2: КОМПИЛЯЦИЯ ПРОГРАММЫ ДЛЯ ПК №1

Скомпилируйте файл `MakcuUdpSender.cpp` в отдельный exe-файл:

### Вариант A: Visual Studio
1. Создайте новый проект "Console Application"
2. Добавьте файл `MakcuUdpSender.cpp`
3. В свойствах проекта укажите дополнительные библиотеки: `ws2_32.lib`
4. Скомпилируйте в Release режиме

### Вариант B: Командная строка MSVC
```cmd
cl /EHsc /O2 MakcuUdpSender.cpp ws2_32.lib /Fe:MakcuUdpSender.exe
```

### Вариант C: MinGW
```cmd
g++ -std=c++17 -O2 MakcuUdpSender.cpp -lws2_32 -o MakcuUdpSender.exe
```

---

## 📋 ШАГ 3: НАСТРОЙКА ПРОГРАММЫ ОТПРАВКИ (ПК №1)

Откройте `MakcuUdpSender.cpp` и измените IP адрес на адрес вашего ПК №2:

```cpp
const char* TARGET_IP = "192.168.1.100"; // <-- Укажите IP ПК №2
const int TARGET_PORT = 9999;            // Порт (можно не менять)
```

Перекомпилируйте после изменения.

---

## 📋 ШАГ 4: НАСТРОЙКА ЧИТА (ПК №2)

В коде чита (обычно `main.cpp` или конфиг) установите режим UDP:

```cpp
pwnz_ai::MakcuConfig config;
config.enable_monitoring = true;
config.enable_udp_listener = true;  // <-- ВКЛЮЧИТЬ UDP РЕЖИМ
config.udp_port = 9999;             // Тот же порт что и в sender

auto makcu = std::make_unique<pwnz_ai::MakcuWrapper>(config);
makcu->Initialize();
```

**ВАЖНО**: В режиме UDP не требуется подключение к COM-порту!

---

## 📋 ШАГ 5: ЗАПУСК

### Порядок запуска:
1. **На ПК №2**: Запустите чит PWNZ AI
   - В консоли должно появиться: `[UDP] Слушаем порт 9999...`
   - И: `[MakcuWrapper] ✓ UDP Monitor thread STARTED on port 9999`

2. **На ПК №1**: Запустите `MakcuUdpSender.exe`
   - В консоли должно появиться: `[SENDER] Хук установлен. Ожидание нажатий...`

3. **Проверка**: Нажмите любую кнопку мыши на ПК №1
   - На ПК №1 в консоли: `[SENDER] Отправлено: ЛКМ -> НАЖАТА`
   - На ПК №2 в консоли: `[UDP] ЛКМ: НАЖАТА` и `[UDP Monitor] ЛКМ (shoot): НАЖАТА`

## 📊 ПРОТОКОЛ ПЕРЕДАЧИ

Формат UDP пакета (2 байта):
| Байт | Значение | Описание |
|------|----------|----------|
| 0 | Тип кнопки | 0x01=ЛКМ, 0x02=ПКМ, 0x04=Колесо, 0x08=Side1, 0x10=Side2 |
| 1 | Состояние | 0x01=нажато, 0x00=отпущено |

Примеры:
- `{0x01, 0x01}` - ЛКМ нажата
- `{0x01, 0x00}` - ЛКМ отпущена
- `{0x02, 0x01}` - ПКМ нажата

## 🔧 УСТРАНЕНИЕ НЕПОЛАДОК

### Проблема: "[UDP] Ошибка bind"
**Решение**: Порт 9999 уже занят другим приложением. Измените порт в обоих файлах.

### Проблема: Не видит нажатия на ПК №2
**Решение**:
1. Проверьте, запущен ли `MakcuUdpSender.exe` на ПК №1
2. Проверьте правильность IP адреса в настройках
3. Отключите брандмауэр Windows на обоих ПК (или добавьте правило для порта 9999)
4. Запустите обе программы от имени администратора

### Проблема: Брандмауэр блокирует соединение
**Решение**: Добавьте правило в брандмауэр Windows:
```cmd
netsh advfirewall firewall add rule name="PWNZ UDP" dir=in action=allow protocol=UDP localport=9999
```

### Проблема: Большая задержка
**Решение**:
1. Используйте проводное Ethernet соединение вместо Wi-Fi
2. Убедитесь, что оба ПК в одной локальной сети
3. Закройте другие программы, использующие сеть

## ⚠️ БЕЗОПАСНОСТЬ

### Detect ли это античитом?
**НЕТ**, если:
- Вы используете локальную сеть (LAN), а не интернет
- На игровом ПК (ПК №2) нет других программ, перехватывающих ввод
- UDP трафик выглядит как обычный сетевой обмен

Античиты не видят:
- Второй компьютер в сети
- UDP пакеты внутри локальной сети
- Программу `MakcuUdpSender.exe` на ПК №1

## 🎯 КАК ЭТО РАБОТАЕТ С КАРТОЙ ЗАХВАТА

Если вы используете карту захвата:
1. Карта захвата передает **видео** с ПК №1 на ПК №2 (односторонний поток)
2. Чит на ПК №2 обрабатывает изображение и видит врагов
3. При обнаружении врага чит отправляет движения мыши обратно на ПК №1 через Makcu
4. **НО**: нажатия кнопок с ПК №1 не передавались обратно на ПК №2 ← ЭТУ ПРОБЛЕМУ МЫ РЕШИЛИ!

Теперь:
- Нажатия кнопок на ПК №1 → UDP → ПК №2 (чит знает, когда вы стреляете)
- Движения мыши от чита на ПК №2 → Makcu → ПК №1 (курсор двигается)

Полная двусторонняя синхронизация! 🎉
